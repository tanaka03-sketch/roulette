# Release Policy

- 対象リポジトリ: `tanaka03-sketch/roulette`
- 作成日: 2026-05-17
- ステータス: 初期運用版

## 目的

リリース単位と変更履歴の残し方を揃え、あとから見返しやすくする。

## バージョニング方針

このリポジトリは当面 `0.y.z` 形式の Semantic Versioning を採用する。

- `0.y.z` の `y`
  - 利用者から見て意味のある機能追加や仕様変更が入るときに上げる
- `0.y.z` の `z`
  - バグ修正、ドキュメント修正、小さな改善で上げる
- `1.0.0`
  - 運用ルール、主要機能、リリース手順が安定してから検討する

## 当面の運用

初期段階では GitHub Releases を手動で作成する。

### リリース作成の流れ

1. `main` の変更内容を確認する
2. 次のバージョン番号を決める
3. `CHANGELOG.md` を更新する
4. GitHub 上でタグ `v0.y.z` を作成する
5. GitHub Release を作成し、変更概要を記載する

## Release Note に含める内容

- 追加した機能
- 修正した不具合
- 開発運用の変更
- 注意点や既知の制約

## 変更履歴との関係

- `CHANGELOG.md` を人が読める正本の変更履歴とする
- GitHub Release は配布単位の記録として扱う

## 今後の拡張候補

- Conventional Commits の本格運用
- changelog 自動生成
- Release 作成の半自動化または自動化
