# ルーレットアプリ 実装タスク分解

- 更新日: 2026-05-15
- 対象要件: `docs/requirements.md`
- 目的: 初期版の要件を、そのまま実装・レビュー・テストに着手できる粒度へ分解する

## 1. 前提

本タスク分解は `docs/requirements.md` を正本として作成する。
以下の前提で実装を進める。

- 認証なし
- 管理画面分離なし
- クライアント完結型
- 状態保持は `localStorage`
- 同名候補は許可し、内部 ID で区別する

## 2. 実装方針

- まずは抽選ロジックと状態モデルを先に固める
- その上で候補管理 UI と抽選 UI を実装する
- `localStorage` 連携と入力バリデーションを後追いではなく初期段階で入れる
- 最後にレスポンシブ対応とテストを詰める

## 3. フェーズ一覧

| フェーズ | 目的 |
| --- | --- |
| Phase 1 | プロジェクト土台とデータモデルを整える |
| Phase 2 | 候補管理機能を実装する |
| Phase 3 | 抽選機能を実装する |
| Phase 4 | 状態保持と例外系を実装する |
| Phase 5 | UI 調整と品質確認を行う |

## 7. レビュー観点

- 抽選ロジックが UI に埋め込まれていないか
- 同名候補を表示名で識別していないか
- `localStorage` の読み書き失敗でアプリが壊れないか
- 抽選済み除外設定の ON / OFF で候補選定が正しく切り替わるか
- リセット対象が「抽選状態のみ」なのか「候補全削除」なのかが UI 上で明確か
- 候補名の表示で XSS が起きないか
